# Agent WebSocket Protocol v1

## Transport

- Endpoint: `platform.url`
- Protocol: WebSocket
- Auth header: `Authorization: Bearer <platform-token>`
- Encoding: UTF-8 JSON text frame
- Default maximum frame: 16 MiB

## Envelope

```json
{
  "version": 1,
  "type": "agent.hello",
  "message_id": "7b4f65a2-df59-4771-8d86-0f19b22f18ed",
  "timestamp": "2026-11-05T12:00:00Z",
  "correlation_id": null,
  "requires_ack": false,
  "payload": {}
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `version` | integer | Must be `1` |
| `type` | string | Dot-separated message type |
| `message_id` | UUID string | Unique ID used for ACK and deduplication |
| `timestamp` | RFC 3339 string | Sender UTC time |
| `correlation_id` | string/null | Request message being answered |
| `requires_ack` | boolean | If true, receiver must send `message.ack` |
| `payload` | object | Type-specific body |

Platform and Agent must deduplicate by `message_id`. A duplicate message must be ACKed again
and must not execute side effects twice.

## ACK

Any received message can be acknowledged. Business-critical Agent-to-platform messages set
`requires_ack=true`.

Platform ACK for an Agent message:

```json
{
  "version": 1,
  "type": "message.ack",
  "message_id": "ac1c34cd-34ed-4685-8bc9-9ba445a7dbb7",
  "timestamp": "2026-11-05T12:00:02Z",
  "correlation_id": "7b4f65a2-df59-4771-8d86-0f19b22f18ed",
  "requires_ack": false,
  "payload": {
    "ack_message_id": "7b4f65a2-df59-4771-8d86-0f19b22f18ed",
    "accepted": true,
    "detail": null
  }
}
```

The Agent resends unacknowledged messages every `ack_timeout_seconds` and after reconnect.
The platform deduplicates by `message_id`.

## Connection Sequence

```text
Agent -> Platform: agent.hello
Agent -> Platform: agent.status
Platform -> Agent: message.ack (may be omitted for hello/status)

loop:
  Agent -> Platform: agent.heartbeat
  Platform -> Agent: ping
  Agent -> Platform: pong
```

## Agent to Platform

### agent.hello

```json
{
  "agent_id": "wechat-agent-01",
  "display_name": "Windows WeChat Agent 01",
  "hostname": "DESKTOP-001",
  "agent_version": "0.1.0",
  "account_alias": "default",
  "capabilities": [
    "wechat.articles.fetch",
    "wechat.login.status",
    "wechat.restart",
    "article.content.optional"
  ],
  "windows_mcp_version": "0.8.5",
  "mcp_tools": ["Snapshot", "Click", "Type", "Scroll", "WaitFor"]
}
```

### agent.heartbeat

```json
{
  "status": "busy",
  "task_id": "task-20261105-001",
  "wechat_state": "busy",
  "uptime_seconds": 3842,
  "outbox_size": 0
}
```

`status` is one of `idle`, `busy`, `degraded`, `offline`.

### task.accepted

```json
{
  "task_id": "task-20261105-001",
  "accepted_at": "2026-11-05T12:00:01Z"
}
```

### task.rejected

```json
{
  "task_id": "task-20261105-002",
  "reason": "agent_busy",
  "active_task_id": "task-20261105-001"
}
```

### task.progress

```json
{
  "task_id": "task-20261105-001",
  "seq": 6,
  "stage": "listing",
  "percent": 48,
  "message": "Reading article list screen 4",
  "data": {
    "article_count": 9
  },
  "emitted_at": "2026-11-05T12:00:18Z"
}
```

`seq` is monotonically increasing for one task. `emitted_at` is generated by the Agent.

```json
  "account_name": "Example Official Account",

  "articles": [

      "title": "Example article title",

      "summary": "Visible summary if any",

      "content_markdown": null,
      "visible_index": 0,

    }
  ],
  "complete": true,
  "screens_scanned": 4,
  "started_at": "2026-11-05T12:00:00Z",

  "diagnostics": {
    "stop_reason": "requested_count_reached",
    "detail_failures": [],
    "login_state": "logged_in"
  }

```

### task.failed

```json
{
  "task_id": "task-20261105-001",
  "code": "ui_goal_not_reached",
  "message": "Goal was not reached after 8 actions",
  "retryable": true,
  "details": {},
  "failed_at": "2026-11-05T12:00:30Z"
}
```

Stable error code prefixes:

- `wechat_*`: login, process, window, or account state
- `ui_*`: UI interaction or verification
- `llm_*`: model response or endpoint
- `mcp_*`: windows-mcp or tool failure
- `agent_*`: local Agent lifecycle
- `protocol_*`: message contract violation

### task.cancelled

```json
{
  "task_id": "task-20261105-001",
  "reason": "Cancelled by platform",
  "cancelled_at": "2026-11-05T12:00:30Z"
}
```

### wechat.login_required

```json
{
  "status": "login_required",
  "task_id": "task-20261105-001",
  "account_alias": "default",
  "message": "WeChat login is required",
  "screenshot_data_url": "data:image/png;base64,..."
}
```

The screenshot can be disabled with `wechat.send_login_screenshot=false`. Platform should
treat this as a user-action state and create a new task after login; it should not use an
endless task timeout as the authorization mechanism.

## Platform to Agent

### task.fetch_articles

```json
{
  "task_id": "task-20261105-001",
  "account_name": "Example Official Account",
  "latest_count": 10,
  "options": {
    "include_content": false,
    "max_detail_articles": 5,
    "max_scroll_screens": 30
  }
}
```

`task_id` must be globally unique and idempotent. If the Agent already completed the same
`task_id`, it resends the prior terminal message instead of rerunning the UI flow.

### task.cancel

```json
{
  "task_id": "task-20261105-001",
  "reason": "User cancelled"
}
```

Cancellation is cooperative. It is checked before every UI action, progress update, article
detail, and model call boundary. The Agent emits `task.cancelled` only when the task reaches
the cancellation boundary.

### wechat.restart

Empty payload. The Agent rejects this while a task is active.

```json
{}
```

### ping

```json
{
  "server_time": "2026-11-05T12:00:00Z"
}
```

Agent responds with `pong` and the same payload.

## Error Codes

| Code | Retryable | Meaning |
| --- | --- | --- |
| `wechat_login_required` | yes | User must scan/login on this machine |
| `ambiguous_account` | no | Exact account missing or ambiguous |
| `ui_goal_not_reached` | yes | UI flow exhausted its action budget |
| `mcp_connection_error` | yes | windows-mcp unavailable |
| `mcp_tool_error` | usually | A specific MCP tool failed |
| `llm_error` | yes | Model endpoint or structured response failure |
| `agent_busy` | yes after current task | Single-UI-task concurrency guard |
| `protocol_error` | no | Invalid or unsupported message |
